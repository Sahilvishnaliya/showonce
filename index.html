Learn & repeat

It learns the rule, not just the moves

Anyone can replay a recording. ShowOnce infers the rule behind your demonstration — “sort by colour into the matching bin” — with Muse Wonder compiling the demonstration into a robot program. Shuffle the bench, and the robot still gets it right, because it learned the intention.

  • Demonstration → task graph → executable pick-and-place program
  • Generalizes to new arrangements it has never seen
  • Every program is readable JSON, not a black box

Verify

The robot checks its own work

After every run, ShowOnce looks at the bench again and scores itself: is every object in the bin the rule demands? A robot that verifies is a robot you can leave alone with the boring work.

  • Post-run vision check against the learned rule
  • Per-object pass/fail, with a session score
  • Failures are reported, never hidden

How ShowOnce works

A human does the task once, on camera. SAM 3.1 tracks each object's mask from start to finish.

02

Muse Wonder compiles the demonstration into a program — and infers the rule, so new arrangements work too.

03

Vision checks the final bench against the rule and scores the run. The robot grades its own homework.

FAQs

Do I need a real robot arm?

No. ShowOnce ships with a simulated 2-link arm so the full loop — demonstrate, learn, repeat, verify — runs anywhere. The learned program is plain JSON pick-and-place, the same shape a real arm controller consumes.

What tasks can it learn?

Any pick-and-place task where the rule is visible in one demonstration: sorting by colour, kitting parts into bins, packing items in a demonstrated order. If a person can show it once, ShowOnce can learn it.

How does it handle a rearranged bench?

It doesn't memorize positions — it learns the rule (for example, colour → bin). Planning happens from the live object positions at run time, so shuffled benches are the normal case, not an edge case.

Which models does it use?

SAM 3.1 for object masks and tracking, Muse Wonder for demonstration-to-program compilation. The rule inference, planning, and verification are deterministic code you can read and test.

Is my camera feed stored?

No. Frames go only to the Meta API you configure, for segmentation. Sessions keep event text and scores, not video.
